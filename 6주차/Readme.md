[버블정렬]
  버블 정렬은 인접한 두 개의 원소를 비교하여 조건에 맞지 않으면 자리를 바꾸는 과정을 반복하여 큰 값을 오른쪽 끝으로 밀어내며 정렬을 수행하는 방식

동작 원리 (오름차순 기준)
배열의 첫 번째 원소부터 시작하여 인접한 바로 다음 원소와 크기를 비교함
앞의 원소가 뒤의 원소보다 크면 두 원소의 위치를 교환(Swap)함
다음 위치로 이동하여 배열 끝까지 반복함 (1회전 완료 시 가장 큰 값이 맨 뒤에 확정됨)
확정된 위치를 제외하고 다시 처음부터 인접한 원소들을 비교함
정렬할 영역이 남지 않을 때까지 반복

시간 복잡도 : O(N^2) (최선, 평균, 최악 모두 동일 / 조기 종료 최적화 시 최선 O(N))
공간 복잡도 : O(1) (추가 메모리를 거의 사용하지 않는 제자리 정렬)
안정성 : 안정 정렬(Stable Sort) - 동일한 값의 기존 상대적 순서가 유지됨

장점: 구현이 매우 간단하고 직관적이다. 중복된 값의 순서가 유지되는 안정 정렬이다.
단점: 원소 간의 교환(Swap) 작업이 너무 자주 일어나 기초 정렬 알고리즘 중에서도 가장 느린 편이다.

[삽입정렬]
  삽입 정렬은 이미 정렬된 앞부분의 배열 영역에 새로운 원소를 적절한 위치에 '삽입'해 나가는 방식으로 정렬을 수행하는 방식

동작 원리 (오름차순 기준)
두 번째 원소(인덱스 1)부터 시작하여 현재 위치의 값(key)을 별도로 저장함
key 값과 그 왼쪽에 있는 정렬된 원소들을 역순으로 비교함
key보다 큰 원소를 발견하면 그 원소를 오른쪽으로 한 칸 이동(Shift)시킴
key보다 작은 원소를 만나거나 배열의 맨 앞에 도달하면 그 바로 오른쪽에 key 값을 삽입함
이 과정을 배열의 끝까지 반복

시간 복잡도 : 최선 O(N), 평균/최악 O(N^2)
공간 복잡도 : O(1) (추가 메모리를 거의 사용하지 않는 제자리 정렬)
안정성 : 안정 정렬(Stable Sort) - 동일한 값의 기존 상대적 순서가 유지됨

장점: 코드가 간단하고 데이터가 이미 거의 정렬되어 있는 경우 O(N)에 가까운 매우 빠른 속도를 보인다. 안정 정렬이다.
단점: 배열의 크기가 크거나 역순으로 정렬된 데이터일 경우 데이터 이동(Shift) 횟수가 많아져 효율성이 떨어진다.

[선택정렬] 
  선택 정렬은 제자리 정렬 알고리즘의 하나로, 배열에서 가장 작은(또한 가장 큰) 값을 찾아 맨 앞에 있는 값과 교환하는 과정을 반복하여 정렬을 수행하는 방식

- 동작 원리 (오름차순 기준)
배열의 첫 번째 위치부터 시작하여 전체 원소 중 최솟값을 찾
찾은 최솟값을 배열의 첫 번째 위치의 값과 맞바꿈(Swap).
첫 번째 위치를 제외한 나머지 원소 중 최솟값을 찾음
찾은 최솟값을 두 번째 위치의 값과 맞바꿈
이 과정을 배열의 끝까지 반복

시간 복잡도 : O(N^2) (최선, 평균, 최악 모두 동일)
공간 복잡도 : O(1) (추가 메모리를 거의 사용하지 않는 제자리 정렬)
안정성 : 불안정 정렬(Unstable Sort) - 동일한 값의 상대적 순서가 바뀔 수 있음

장점: 코드 구조가 매우 직관적이고 구현하기 쉽다.데이터 교환(Swap) 횟수가 최대 N-1번으로 적다.
단점: 배열이 이미 정렬되어 있더라도 모든 원소를 비교하므로 항상 O(N^2)의 시간이 걸려 효율성이 떨어진다.
