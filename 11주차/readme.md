C언어 구조체 문제

[문제 1] 다음 중 C언어의 구조체 변수 대입에 관한 설명으로 가장 올바른 것은?

1. 구조체 변수끼리는 대입 연산자(=)를 사용할 수 없으므로 반드시 memcpy 함수를 써야 한다.
2. person2 = person1;을 실행하면 person1의 모든 멤버 값이 person2에 동일하게 복사된다.
3. 구조체 멤버로 배열이 포함되어 있을 경우, 대입 연산자(=)를 사용하면 배열의 내부 값까지 자동으로 깊은 복사(Deep Copy)된다.
4. 구조체 변수 간의 대입은 포인터 변수(*)를 통해서만 가능하다.

정답: 2)
해설:
1번: C언어에서는 같은 구조체 타입의 변수끼리 대입 연산자(=)를 사용하는 것을 허용한다
3번: 대입 연산자를 사용하면 배열 멤버의 경우 주소값이나 전체 블록이 단순 복사(얕은 복사)될 뿐, 내부 원소까지 알아서 깊은 복사가 일어나지는 않는다.
4번: 틀구조체 변수 간의 대입은 일반 구조체 변수끼리도 대입 연산자로 바로 가능하므로 포인터만 써야 한다는 것은 틀린 설명이다.


[문제 2] 다음 중 struct Person의 인스턴스를 가리키는 포인터 p가 있을 때, 멤버 변수 name에 접근하는 올바른 표현을 모두 고른 것은?

[보기]
ㄱ. p.name
ㄴ. p->name
ㄷ. (*p).name
ㄹ. *p->name

정답: ㄴ, ㄷ
해설:
ㄱ(p.name) : p는 구조체 변수 자체가 아니라 주소를 담고 있는 포인터이므로 점(.) 연산자가 아니라 화살표 연산자를 써야 하기 때문에 틀렸다.
ㄹ(*p->name): 연산자 우선순위에 의해 *(p->name)으로 먼저 해석되어 name 멤버 안의 값에 접근하려 하므로 문법 오류나 오작동이 발생하기 때문에 틀렸다.


[문제 3] 다음 중 공용체에 대한 설명으로 가장 적절하지 않은 것은?

1. 공용체는 구조체와 선언 형식이 유사하지만 struct 대신 union 키워드를 사용한다.
2. 공용체의 모든 멤버는 메모리의 시작 주소를 공유한다.
3. 공용체 변수는 여러 멤버의 값을 동시에 각각 독립적으로 안전하게 저장하고 유지할 수 있다.
4. 메모리를 절약하거나 여러 가지 자료형을 같은 메모리 위치에 겹쳐서 사용해야 할 때 유용하다.

정답: 3)
해설:
3번 : 공용체는 공간을 공유하기 때문에 여러 멤버에 서로 다른 값을 동시에 저장하면 나중에 넣은 값에 의해 이전 값이 덮어씌워져서 독립적으로 유지될 수 없기 때문에 틀린 설명이다.


[문제 4] 다음 중 열거형을 사용하는 주된 이유와 특징으로 가장 거리가 먼 것은?

1. 정수형 상수들에 직관적인 이름을 부여하여 코드의 가독성과 유지보수성을 높인다.
2. switch 문의 case 값 등으로 사용하여 프로그램의 의도를 명확히 표현할 수 있다.
3. 기본적으로 첫 번째 상수는 0부터 시작하여 1씩 증가하는 값이 자동으로 할당된다.
4. 열거형 내부의 멤버 상자들은 공용체처럼 메모리 공간을 서로 겹쳐서 공유하는 방식으로 동작한다.

정답: 4)
해설:
4번 : 열거형은 단순히 연관된 정수 상수를 보기 쉽게 나열한 것일 뿐, 공용체처럼 메모리 공간을 겹쳐서 공유하는 자료형이 아니다.


[문제 5] 다음 중 구조체를 함수의 인자로 전달할 때, 구조체 포인터(주소)를 매개변수로 사용하는 이유로 가장 알맞은 것은?

1. 구조체의 복사본을 생성하여 전달하므로 원본 데이터가 절대 변경되지 않도록 보호하기 위해
2. 함수에 전달될 때 구조체 전체가 복사되어 전달되므로 코드의 실행 속도를 늦추기 위해
3. 구조체의 크기가 클 때 불필요한 메모리 복사를 줄이고, 함수 내부에서 원본 구조체의 데이터를 직접 수정할 수 있도록 하기 위해
4. 구조체 내부의 멤버 변수가 모두 포인터형일 때만 함수 인자로 받을 수 있는 문법적 제약 때문에

정답: 3)
해설:
1번 : 복사본을 전달해 원본을 보호하는 방식인 값에 의한 전달에 대한 설명이므로 포인터를 쓰는 이유와 거리가 멀다.
2번 : 실행 속도를 일부러 늦춘다는 잘못된 표현이 들어가 있어 틀린 설명이다.
4번 : 구조체 내부 멤버의 형태와 함수 인자 전달 방식은 아무런 문법적 제약 관계가 없으므로 틀린 설명이다.
